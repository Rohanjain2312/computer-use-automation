# Evidence

Everything here was produced by running the system, not by hand. Paths are
exactly as the tools wrote them.

Reproduce all of it with `./scripts/demo.sh` (needs `ANTHROPIC_API_KEY`), or
everything except the discovery run with `./scripts/replay.sh` (needs no model
access, because replay never uses one).

Redaction on the way out, stated precisely:

* **Secrets never appear anywhere.** The operator passcode and the supervisor
  override code are registered with the redactor before the run starts, and
  secret input fields are masked with an opaque overlay *before* each screenshot
  is taken.
* **Replay evidence carries no PII.** Outputs typed `pii` are returned to the
  caller and redacted in everything written to disk; an end-to-end test asserts
  the member name is absent from `result.json`.
* **Discovery evidence necessarily contains what was on screen.** Discovery is
  where sensitivity is *learned* — the agent classifies `member_name` as `pii`
  partway through the run, and from that moment the value is registered and
  masked in everything written afterwards. What was captured before it (the
  screenshots, the observation the model was shown, the accessibility snapshot)
  still shows the record. That is inherent, not an oversight, and it is why
  discovery runs against synthetic fixture data. See `REPORT.md` § Safety.

## 2. The artifact

`artifacts/member_savings_balance_lookup.v1.0.0.json` (the live copy is
`/artifacts/member_savings_balance_lookup/v1.0.0.json`)

7 steps · 3 typed inputs · 3 typed outputs · 2 business outcomes · 1 recovery
rule · 1 failure rule · checksummed · `status: approved`, with the run id that
verified it recorded in `verification`.

Worth looking at:

* **`steps[*].target.strategies`** — each step carries a ranked list with a
  confidence and a written rationale, generated by measuring how many other
  controls on that screen each strategy also matched.
* **`outputs[2]`** (`member_name`) — found by `label_proximity` on "Member
  Name", not by the name it happens to hold. Marked `pii`: returned to the
  caller, redacted in everything written to disk.
* **`steps[*].checkpoint`** — screen labels ("Member Servicing — Inquiry"), never
  record data. Synthesis rejects any candidate containing a value the run was
  given or read.
* **`inputs[1]`** (`operator_passcode`) — `sensitivity: secret`,
  `source: environment`. The artifact says where to type it, never what it is.

`artifacts/capability_tools.json` is the same artifact projected into a
JSON-schema tool definition for a calling agent. Note that the credential inputs
are absent: an agent cannot pass them and should not know they exist.

### The handoff run in detail

`replay_handoff_20260917T222929Z_4c8cf0/result.json`

Member 100999 is entitlement-restricted. The artifact declares that as a
business outcome with `disposition: escalate_to_human` — a real answer a person
can clear.

1. Replay detects it, pauses, and writes an intervention request
   (`int_*.json`) carrying the goal, the step, the reason, an excerpt of the
   screen, a screenshot and a DOM snapshot.
2. Control transfers. `control_log` records the ordering:
   `automation_paused → control_granted → control_released → automation_resumed`.
3. The operator acts **on the same live session** — same browser context, same
   cookies, same page. Seven actions were recorded by in-page listeners, not
   assumed:

   ```
   clicked the 'Supervisor Override' button
   clicked the 'Override Code' textbox
   frame 'bodypane' moved to a new page
   entered a value into 'Override Code'
   clicked the 'Apply Override' button
   submitted form 'f1'
   ```

4. Control returns. The engine **re-verifies the step's checkpoint before
   repeating any work** — the operator had already produced the state the step
   was reaching for, so re-running it would have hunted for a control that was
   no longer on screen.
5. The run completes, returning the restricted member's savings balance of `27640.18` and status `OPEN`.

The override code does not appear anywhere in the run's output — it is supplied
via `MERIDIAN_OVERRIDE_CODE` and registered with the redactor before anything is
written. An end-to-end test asserts this.

**What is simulated here, precisely.** This run used the `ScriptedOperator`, so
that the handoff is reproducible headlessly and in CI. It is not a shortcut
around the seam: it takes control through the same state machine, acts on the
same live session, and is recorded by the same in-page listeners. Every action
it records is tagged `"simulated": true`, so this evidence never overstates
what happened. For a real person, run `./scripts/handoff_demo.sh`, which uses
`--headed --operator console`: the run pauses, you take control in the browser
window the automation is driving, do the override yourself, and release.
